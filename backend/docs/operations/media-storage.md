# Media and profile avatars

User profile images remain disabled; profile avatars are generated by the
frontend from the user's name. Public active-member cards are the exception:
administrators can upload an optional JPEG, PNG, or WebP photo (up to the
configured `MAX_UPLOAD_SIZE_MB`, 5 MB by default). The API validates the image
and stores it using Django's configured default media storage.

For Supabase Storage, configure `STORAGE_BACKEND=supabase`, `SUPABASE_URL`,
`SUPABASE_SERVICE_ROLE_KEY`, and `SUPABASE_STORAGE_BUCKET`. The service-role
key is a backend secret and must never be included in frontend variables or
bundled assets. Active-member photos use the `founding-members/` prefix. Those
member photos are publicly displayed. Django issues expiring signed URLs, so
the bucket can remain private; `SUPABASE_SIGNED_URL_TTL` controls URL lifetime
(3600 seconds by default). The public member endpoint caches responses for
five minutes, less than the default URL lifetime. Local development can keep
`STORAGE_BACKEND=local`; the same field will use `MEDIA_ROOT` there.

The homepage hero uses media shipped with the frontend under `frontend/public`
and does not use database-backed slider records or Supabase storage. No object
cleanup is performed when member records are edited or removed; if cleanup is
later required, first inventory referenced objects and agree on a recovery
plan.
